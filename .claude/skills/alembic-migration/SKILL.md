# Alembic migrations

Migration files are a graded deliverable. They must apply cleanly from empty, reverse cleanly,
and match the models.

## Procedure

1. **Change the SQLAlchemy model first.** The models are the source of truth; the migration
   follows.

2. **Autogenerate, then rewrite.**
   ```bash
   docker compose exec api alembic revision --autogenerate -m "add_quiz_choice_constraints"
   ```
   Autogenerate is a **draft**. It reliably misses: partial indexes, expression indexes, `CHECK`
   constraints, server defaults, enum value additions, and every data migration. Read the
   generated file line by line and fix it.

3. **Write `downgrade()` for real.** Not `pass`. A migration that cannot reverse cannot be tested
   and will not be trusted. Drop in reverse dependency order.

4. **Verify the round trip** — this is the step that catches most problems:
   ```bash
   docker compose exec api alembic upgrade head
   docker compose exec api alembic downgrade -1
   docker compose exec api alembic upgrade head
   ```
   Then verify from empty:
   ```bash
   docker compose down -v && docker compose up -d
   docker compose exec api alembic upgrade head
   ```

5. **Check for drift.** After upgrading, autogenerate again — it must produce an empty migration.
   Anything it wants to change is model/migration divergence. Delete the throwaway file.

6. **Commit the migration with the model change**, never separately.

## Project-specific rules

**Expression and partial indexes must be written by hand.** The invariants this project relies on
are not autogenerated:

```python
op.create_index(
    "ux_choice_text", "quiz_choices",
    [sa.text("question_id"), sa.text("lower(btrim(text))")], unique=True,
)
op.create_index(
    "ux_choice_correct", "quiz_choices", ["question_id"],
    unique=True, postgresql_where=sa.text("is_correct"),
)
```

**Generated `tsvector` columns** are declared in the migration, not maintained in Python:

```python
op.add_column("document_chunks", sa.Column(
    "tsv", postgresql.TSVECTOR,
    sa.Computed("to_tsvector('english', content)", persisted=True),
))
op.create_index("ix_chunks_tsv", "document_chunks", ["tsv"], postgresql_using="gin")
```

**Every foreign key states its `ondelete`.** No exceptions, no relying on defaults.

**Enums:** use a native Postgres enum with an explicit name, and remember `downgrade()` must drop
the type after dropping the columns that use it. Adding a value to an existing enum requires
`ALTER TYPE ... ADD VALUE`, which cannot run inside a transaction — set
`transactional_ddl = False` for that revision or use a text column with a `CHECK`.

**Indexes on large tables:** prefer `CREATE INDEX CONCURRENTLY` (requires disabling the
transaction for that revision). For this project's data volumes it is optional — but if you skip
it, say why in a comment.

## When a migration fails

Do not edit an already-applied migration to fix it — write a new one. Editing history breaks any
database that already ran it. The only exception is a migration that has never left your working
tree and is not yet committed.

If the chain is broken (`Can't locate revision`), check `down_revision` values across the files —
usually two branches from the same parent. Merge with `alembic merge`.
